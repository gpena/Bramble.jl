Grid spaces and discrete functions#

What you will learn. How to put a function on a mesh, measure it, and stack copies into a composite space with vector elements.

What you need first. The mesh tutorial, for building a mesh; the geometry tutorial, for the domain it sits on.

Where next. Difference operators, which act on the elements built here.

A grid space is the discrete function space over a mesh. It fixes how many degrees of freedom a field has and which quadrature weight each one carries. A VectorElement is a function in that space. Every block below runs when this page is built.

The running problem is small: sample \(f(x) = \sin(\pi x)\) on the unit interval and measure it, first as one field, then as a pair of fields.

A grid space over a mesh#

gridspace builds a grid space over a mesh. ndofs counts its degrees of freedom, and with Tuple it gives the grid shape:

using Bramble
import Bramble: component_range, component_ranges, weights

Ω = domain(interval(0.0, 1.0))
Ωₕ = mesh(Ω, 11)
Wₕ = gridspace(Ωₕ)

ndofs(Wₕ), ndofs(Wₕ, Tuple)
(11, (11,))

There is one degree of freedom per mesh point. points(Wₕ) is points(Ωₕ), so the space and its mesh agree on where the degrees of freedom sit.

Discrete functions#

Rₕ restricts a function to the grid: it evaluates it at every point and returns a VectorElement, the discrete function.

uₕ = Rₕ(Wₕ, x -> sin(π * x))

length(uₕ), uₕ[6]
(11, 1.0)

VectorElement <: AbstractVector, so indexing, length and broadcasting work as usual, and broadcasting keeps the parent space:

wₕ = 3.0 .* uₕ .+ element(Wₕ, 2.0)

space(wₕ) === Wₕ, wₕ[6]
(true, 5.0)

element allocates a field, optionally filled with a constant. Rₕ! writes into an element that already exists, which is what a time loop wants.

Inner products and norms#

Each degree of freedom carries a quadrature weight, the cell measure around its point. innerₕ weights each point by it, and normₕ is the norm it induces:

\[(u_h, v_h)_h = \sum_i |\square_i| \, u_h(x_i) v_h(x_i), \qquad \|u_h\|_h = \sqrt{(u_h, u_h)_h}.\] 
vₕ = Rₕ(Wₕ, x -> cos(π * x))

innerₕ(uₕ, vₕ), normₕ(uₕ), normₕ(uₕ)^2 ≈ innerₕ(uₕ, uₕ)
(-5.148621912560444e-18, 0.7071067811865476, true)

The norm of \(\sin(\pi x)\) on \([0, 1]\) is \(1/\sqrt{2} \approx 0.707\), which normₕ reproduces here. The discrete Sobolev norms are built on the backward gradient \(\nabla_{-h}\):

\[|u_h|_{1,h}^2 = \sum_{d=1}^D \|D_{-x_d} u_h\|_h^2, \qquad \|u_h\|_{1,h}^2 = \|u_h\|_h^2 + |u_h|_{1,h}^2.\] 
snorm₁ₕ(uₕ), norm₁ₕ(uₕ), norm₁ₕ(uₕ)^2 ≈ normₕ(uₕ)^2 + snorm₁ₕ(uₕ)^2
(2.212317420824743, 2.322573652327229, true)

Try this

Build the mesh as mesh(Ω, 11, false), a non-uniform one with the same number of points, and rerun the blocks above. ndofs is unchanged, but the weights are no longer all equal, so normₕ and innerₕ change while still tiling the interval. The mesh tutorial builds such meshes on purpose.

Composite spaces and vector elements#

A composite space stacks copies of a space for a vector field or a coupled system. Its elements are VectorElements too: one flat vector holding every component, one after another. Wₕ^Val(N) stacks N copies:

Vₕ = Wₕ^Val(2)

ncomponents(Vₕ), ndofs(Vₕ), ndofs(Vₕ, Tuple)
(2, 22, (11, 11))

ndofs(Vₕ, Tuple) is one entry per component, not a grid shape. A component is one of the stacked fields, and calling a composite element with i returns the i-th component as a view:

uvec = element(Vₕ)
uₓ = uvec(1)
uᵧ = uvec(2)

uₓ .= 1.5
uᵧ .= -2.0

parent(uvec)[[1, 12]]
2-element Vector{Float64}:
  1.5
 -2.0

The component is a zero-copy view, so writing to it writes through to the parent. For a scalar space uₕ(1) is uₕ itself. components destructures the lot:

c₁, c₂ = components(uvec)

c₁ === uₓ, c₂ === uᵧ
(true, true)

On a composite space Rₕ! takes a tuple of scalar functions, or one function returning a tuple, and innerₕ sums over components:

Rₕ!(uvec, (x -> sin(π * x), x -> cos(π * x)))

normₕ(uvec)^2 ≈ normₕ(uvec(1))^2 + normₕ(uvec(2))^2
true

Try this

Replace Val(2) with Val(3) and add a third function to the tuple. ncomponents and ndofs follow, and every other line of this section stays the same.

Reference#

Constructors#

Wₕ^Val(N) is type stable whatever N is, while Wₕ^2 relies on the literal being constant-folded and only reaches N ≤ 3. vector_gridspace(Ωₕ, 2) builds the same space straight from a mesh, and CompositeGridSpace((Wₕ, Wₕ)) builds one from spaces that need not be identical:

spaces(Vₕ) == (Wₕ, Wₕ)
true

Weights#

weights(Wₕ) returns the whole SpaceWeights bundle, and a weight vector comes from naming the inner product it belongs to. Bramble.Innerh and Bramble.Innerplus are public but not exported, hence the prefix. weights is not defined for a composite space, since its leaves may live on different meshes: call it on a components leaf instead.

w = weights(Wₕ, Bramble.Innerh())

length(w), sum(w)      # one weight per point; they tile the unit interval
(11, 1.0)

Component ranges#

component_range and component_ranges give the degrees of freedom each component owns:

component_range(Vₕ, 1), component_ranges(Vₕ)
(1:11, (1:11, 12:22))

Functions as factors#

A plain Function is not a grid function, so multiplying by one restricts it first (Rₕ(space(uₕ), f)) and scales pointwise. This is what lets a spatial condition multiply a field directly, including inside a form:

oneₕ = Rₕ(Wₕ, x -> 1.0)
below_half = (x -> x[1] < 0.5) * oneₕ

sum(below_half)
5.0

Grid layout#

Degrees of freedom are stored flat, but on a two-dimensional space a scalar element also indexes by grid coordinate, with a CartesianIndex, without reshaping:

W₂ = gridspace(mesh(domain(box((0.0, 0.0), (1.0, 1.0))), (5, 5), (true, true)))
V₂ = W₂^Val(2)
u_scal = element(W₂, 0.0)
u_scal[CartesianIndex(2, 3)] = 10.0
u_scal[CartesianIndex(4, 1)] = 20.0

u_scal[CartesianIndex(2, 3)], u_scal[CartesianIndex(4, 1)]
(10.0, 20.0)

For matrix operations or plotting, reshape(uₕ) returns a Base.ReshapedArray view of the same memory, so writing through it writes through to the element. On a composite element it returns one view per component:

u_grid = reshape(u_scal)
u_grid[2, 3] = -1.0

size(u_grid), u_scal[CartesianIndex(2, 3)], size.(reshape(element(V₂)))
((5, 5), -1.0, ((5, 5), (5, 5)))

Restriction and cell averaging#

Two ways to turn a continuous function into a grid function. Nodal restriction \(R_h\) evaluates it at the grid points; cell averaging \(\mathrm{avg}_h\) integrates it over the cell around each point and divides by the cell measure:

\[\mathrm{avg}_h f(x_i) = \frac{1}{|\square_i|} \int_{\square_i} f(x) \, dx\]

Rₕ allocates and Rₕ! writes in place. avgₕ and avgₕ! mirror them, using a tensor-product Gauss-Legendre rule (AVG_QUAD_POINTS = 6, exact through degree eleven):

u_avg = avgₕ(W₂, x -> exp(-x[1] - x[2]))
avgₕ!(u_avg, x -> exp(-x[1] - x[2]))

u_avg[1]
0.8836465857416996

The difference matters for a source term: Rₕ of a rough function inherits its roughness, while avgₕ integrates it away.

Staggered inner product#

inner₊ is the staggered counterpart of innerₕ: it weights by the half-spacings, the interface quantities a difference or a gradient lands on, and a trailing :x/:y/:z (or 1/2/3) argument picks a single direction. That pairing is what makes summation by parts exact; the operators tutorial derives it.

D = ∇ₕ(uₕ)

inner₊(D, D, :x) ≈ snorm₁ₕ(uₕ)^2
true
