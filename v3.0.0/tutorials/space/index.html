Grid spaces and discrete functions

A grid space is the discrete function space over a mesh: it fixes how many degrees of freedom a field has and which quadrature weight each one carries. A VectorElement is a function in that space. Every block below runs when this page is built.

1. Scalar grid spaces

gridspace builds a ScalarGridSpace over a mesh:

using Bramble

Ω = domain(box((0.0, 0.0), (1.0, 1.0)))
Ωₕ = mesh(Ω, (5, 5), (true, true))    # uniform spacing along both axes
Wₕ = gridspace(Ωₕ)

ndofs(Wₕ), ndofs(Wₕ, Tuple)
(25, (5, 5))

ndofs counts the grid points; with Tuple it gives the grid's shape.

Each degree of freedom carries a quadrature weight, the cell measure around its point. weights(Wₕ) returns the whole SpaceWeights bundle, and a weight vector comes from naming the inner product it belongs to. Bramble.Innerh and Bramble.Innerplus are public but not exported, hence the prefix:

w = weights(Wₕ, Bramble.Innerh())

length(w), sum(w)      # one weight per point; they tile the unit square
(25, 1.0)

2. Composite spaces

A CompositeGridSpace stacks copies of a space for a vector field or a coupled system:

Vₕ = Wₕ^Val(2)

ncomponents(Vₕ), ndofs(Vₕ)
(2, 50)

Wₕ^Val(N) is the spelling used throughout this manual: it is type stable whatever N is, while Wₕ^2 relies on the literal being constant-folded and only reaches N ≤ 3. vector_gridspace(Ωₕ, 2) builds the same space straight from a mesh, and CompositeGridSpace((Wₕ, Wₕ)) builds one from spaces that need not be identical.

ndofs(Vₕ, Tuple), spaces(Vₕ) == (Wₕ, Wₕ)
((25, 25), true)

ndofs(Vₕ, Tuple) is one entry per component, not a grid shape. weights is not defined for a composite space at all, since its leaves may live on different meshes: call it on a components leaf instead.

3. Vector elements

element allocates a field, optionally filled with a constant:

uₕ = element(Wₕ)         # uninitialized
u_zero = element(Wₕ, 0.0)

length(u_zero), u_zero[1]
(25, 0.0)

VectorElement <: AbstractVector, so indexing, length and broadcasting work as usual, and broadcasting keeps the parent space:

vₕ = element(Wₕ, 2.0)
wₕ = 3.0 .* u_zero .+ vₕ

space(wₕ) === Wₕ, wₕ[1]
(true, 2.0)

A plain Function is not a grid function, so multiplying by one restricts it first (Rₕ(space(uₕ), f)) and scales pointwise. This is what lets a spatial condition multiply a field directly, including inside a form:

oneₕ = Rₕ(Wₕ, x -> 1.0)
below_half = (x -> x[1] < 0.5) * oneₕ

sum(below_half)
10.0

4. Components

Calling an element returns the i-th component as a view:

uvec = element(Vₕ)
uₓ = uvec(1)
uᵧ = uvec(2)

uₓ .= 1.5
uᵧ .= -2.0

parent(uvec)[[1, 26]]
2-element Vector{Float64}:
  1.5
 -2.0

The component is a zero-copy view, so writing to it writes through to the parent. For a scalar space uₕ(1) is uₕ itself. component_range and component_ranges give the degrees of freedom each component owns, and components destructures the lot:

component_range(Vₕ, 1), component_ranges(Vₕ)
(1:25, (1:25, 26:50))
c₁, c₂ = components(uvec)

c₁ === uₓ, c₂ === uᵧ
(true, true)

5. Grid layout

Degrees of freedom are stored flat, but a scalar element also indexes by grid coordinate, with a tuple or a CartesianIndex, without reshaping:

u_scal = element(Wₕ, 0.0)
u_scal[2, 3] = 10.0
u_scal[CartesianIndex(4, 1)] = 20.0

u_scal[2, 3], u_scal[4, 1]
(10.0, 20.0)

For matrix operations or plotting, reshape(uₕ) returns a Base.ReshapedArray view of the same memory, so writing through it writes through to the element. On a composite element it returns one view per component:

u_grid = reshape(u_scal)
u_grid[2, 3] = -1.0

size(u_grid), u_scal[2, 3], size.(reshape(uvec))
((5, 5), -1.0, ((5, 5), (5, 5)))

6. Restriction and cell averaging

Two ways to turn a continuous function into a grid function. Nodal restriction $R_h$ evaluates it at the grid points; cell averaging $\mathrm{avg}_h$ integrates it over the cell around each point and divides by the cell measure:

\[\mathrm{avg}_h f(x_i) = \frac{1}{|\square_i|} \int_{\square_i} f(x) \, dx\]

Rₕ allocates, Rₕ! writes into an element that already exists, which is what a time loop wants:

f(x) = sin(2π * x[1]) * cos(2π * x[2])

u_proj = Rₕ(Wₕ, f)
Rₕ!(u_proj, f)

u_proj[1]
0.0

On a composite space both take a tuple of scalar functions, or one function returning a tuple:

Rₕ!(uvec, (x -> x[1], x -> 2 * x[2]))
Rₕ!(uvec, x -> (sin(x[1]), cos(x[2])))

uvec(1)[1], uvec(2)[1]
(0.0, 1.0)

avgₕ and avgₕ! mirror them, using a tensor-product Gauss-Legendre rule (AVG_QUAD_POINTS = 6, exact through degree eleven):

u_avg = avgₕ(Wₕ, x -> exp(-x[1] - x[2]))
avgₕ!(u_avg, x -> exp(-x[1] - x[2]))

u_avg[1]
0.8836465857416996

The difference matters for a source term: Rₕ of a rough function inherits its roughness, while avgₕ integrates it away.

7. Inner products and norms

innerₕ weights each point by its cell measure, and normₕ is the norm it induces:

\[(u_h, v_h)_h = \sum_i |\square_i| \, u_h(x_i) v_h(x_i), \qquad \|u_h\|_h = \sqrt{(u_h, u_h)_h}.\]

Ω₁ = domain(interval(0.0, 1.0))
W₁ = gridspace(mesh(Ω₁, 100, true))
s = Rₕ(W₁, sin)
c = Rₕ(W₁, cos)

innerₕ(s, c), normₕ(s), normₕ(s)^2 ≈ innerₕ(s, s)
(0.3540246682186028, 0.5221909369935807, true)

The discrete Sobolev norms are built on the backward gradient $\nabla_{-h}$:

\[|u_h|_{1,h}^2 = \sum_{d=1}^D \|D_{-x_d} u_h\|_h^2, \qquad \|u_h\|_{1,h}^2 = \|u_h\|_h^2 + |u_h|_{1,h}^2.\]

snorm₁ₕ(s), norm₁ₕ(s), norm₁ₕ(s)^2 ≈ normₕ(s)^2 + snorm₁ₕ(s)^2
(0.8528317760887776, 1.0000027064888237, true)

On a composite space innerₕ sums over components:

V₁ = W₁^Val(2)
u_vec = Rₕ(V₁, (x -> sin(x[1]), x -> cos(x[1])))

normₕ(u_vec)^2 ≈ normₕ(u_vec(1))^2 + normₕ(u_vec(2))^2
true

inner₊ is the staggered counterpart: it weights by the half-spacings, the interface quantities a difference or a gradient lands on, and inner₊ₓ, inner₊ᵧ, inner₊₂ pick a single direction. That pairing is what makes summation by parts exact; the operators tutorial derives it.

D = D₋ₓ(s)

inner₊ₓ(D, D) ≈ snorm₁ₕ(s)^2
true
